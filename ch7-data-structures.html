7.1 / 7.7 / 7.8 · SPSC 环形缓冲

一个写者、一个读者，为什么可以不加锁

head 只由生产者修改，tail 只由消费者修改，双方各自读对方的指针。只要遵守这个所有权边界，单字节读写天然原子，不需要临界区。先亲手推一遍指针，再看“两个生产者”是怎么把数据写丢的。

8 格环形缓冲

容量 8 · 可用 7
H = 下一次写 T = 下一次读 已排队数据 冲突格
空：head == tail。消费者取走数据后，tail 追上 head。

核心代码：留一格 + 内存序

单生产者 / 单消费者
/* size 必须是 2 的幂，掩码代替取模 */
typedef struct {
  uint8_t *buf; uint32_t size;
  volatile uint32_t head, tail;
} ring_t;

bool ring_put(ring_t *r, uint8_t b) {
  uint32_t next = (r->head + 1) & (r->size - 1);
  if (next == r->tail) return false; /* 满 */
  r->buf[r->head] = b;
  __DMB();              /* 先写数据，再发布 head */
  r->head = next;
  return true;
}

bool ring_get(ring_t *r, uint8_t *b) {
  if (r->tail == r->head) return false; /* 空 */
  *b = r->buf[r->tail];
  __DMB();
  r->tail = (r->tail + 1) & (r->size - 1);
  return true;
}
为什么留一格？如果允许写满，head == tail 就同时表示“空”和“满”。留一格让 head 永远追不上 tail，判定不需要额外计数器。
DMB 放在哪？先写 buf，再发布 head；读者看到新 head 时，数据一定已经可见。Cortex-M 单核通常顺序一致，但编译器重排和双核/弱内存序平台仍然需要它。
边界：只支持 1 写 1 读。多生产者必须关中断、用 CAS，或改成“每生产者私有 ring + 消费者聚合”，不要硬撑无锁。
流派 A · 留一格

实现最简单、无需原子计数；容量损失 1 格。绝大多数字节流首选。

流派 B · 带 count

能存满 size 字节，但 count 的更新需要原子性；只有在“满载不能丢”时才值得。

流派 C · DMA 推导

写指针由硬件 NDTR 反推：wpos = size - __HAL_DMA_GET_COUNTER()；软件零维护，见 ch28。

7.2 / 7.9 · 侵入式链表与 container_of

节点不是“装对象的盒子”，节点就长在对象里

内核风格的双向链表把 prev/next 嵌进业务结构体。插入、删除只改指针，不分配、不拷贝；拿到节点地址后，用 container_of 反推出宿主对象的首地址。点节点看地址怎么算。

container_of：一次指针减法

零运行时开销
#define container_of(ptr, type, member) \
  ((type *)((char *)(ptr) - offsetof(type, member)))

typedef struct task {
  int prio;          /* offset 0  */
  char name[8];       /* offset 4  */
  list_node_t node;  /* offset 12 */
} task_t;

/* p 是 node 的地址，不是 task 的地址 */
task_t *t = container_of(p, task_t, node);
为什么省一次分配？非侵入式链表通常要 malloc 一个节点，再把数据拷进去；侵入式链表的节点生命周期与对象完全一致，删除后对象仍然归业务所有。

遍历时删除的坑

用 _safe 版本
/* 错误：删掉 n 之后还访问 n->next */
list_for_each(p, &g_ready) {
  if (should_drop(p)) list_del(p);
}

/* 正确：先保存下一个节点 */
list_for_each_safe(p, tmp, &g_ready) {
  if (should_drop(p)) list_del(p);
}
Code Review 清单：看到 list_for_each 里出现 list_del，立刻要求换成 list_for_each_safe。这类野指针在低负载测试里往往不出现，现场却会随机死机。
双向链表的代价：每个节点多一个指针；删除后必须把 prev/next 置空或重新初始化，避免“野节点”被二次插入。
7.3 · 静态对象池

把“分配”变成一次链表出栈

启动时把一块静态内存切成固定大小的块，空闲块穿成链表。分配 = 取头节点，释放 = 放回头部；O(1)、无碎片、剩余块数就是泄漏计数器。点击已用块可以释放它。

6 块 × 32 B

点击已用块释放
空闲：6 块可用，free_list 指向 0 号块。

O(1) 分配，代价是什么

池 vs malloc
void pool_init(pool_t *p, void *mem, uint32_t n, size_t sz) {
  p->blk_size = sz; p->cnt = n;
  list_init(&p->free_list);
  for (uint32_t i = 0; i < n; i++)
    list_add_tail(&p->free_list,
      (list_node_t *)((char *)mem + i * sz));
}

void *pool_alloc(pool_t *p) {       /* O(1) */
  if (list_empty(&p->free_list)) return NULL;
  list_node_t *n = p->free_list.next;
  list_del(n); return n;
}
pool_alloc（固定块）~14 cycles
malloc（最坏路径）~200+ cycles，不确定
三条硬约束：① 块大小对齐到 alignof(max_align_t)，池基址至少 8 B 对齐；② 块尺寸固定，峰值必须预估；③ 类型被固定，适合消息、帧、会话这类同构对象。
RTOS 版本：把 free_list 操作包在互斥区里，或用关中断保护；单任务初始化阶段则无需加锁。分配器本身不做“合并”，因此没有外部碎片，但也无法把剩余空间借给更大的对象。
为什么不用 malloc 的“碎片”讲故事：一个 1 KB 的堆，反复分配 16 B / 48 B / 128 B，最后可能还剩 300 B，但没有任何连续块能容纳 256 B。池把“最大连续块”固定成块大小，代价是你必须接受同构对象和容量上限。

把 switch 嵌套换成一张可回放的迁移表

状态机不是“写几个 if”，而是把“当前状态 + 事件 → 下一状态”变成数据。点击事件按钮，观察状态节点、迁移边和日志如何同步。日志是排障时最便宜的时间机器。

事件丢失为什么危险？如果 EV_BTN 在“状态机正忙”时被丢掉，又没有超时兜底，设备会永远停在 IDLE。每条边都要有默认迁移：未知事件 → ERR / 自恢复态，并记录日志。
和 RTOS 的配合：每个任务内部跑一个 FSM，任务从队列取事件喂给 fsm_step()。跨任务协作变成“发事件”，不再抢共享变量，竞态面大幅缩小。这就是 Actor 模型的嵌入式落地。

表驱动：状态只是数组下标

新增状态 = 加一行
typedef st_t (*handler_t)(evt_t e);

static st_t on_idle(evt_t e) {
  if (e == EV_BTN) return ST_RUN;
  return ST_IDLE;
}
/* ... on_run / on_err ... */

static const handler_t tab[] = {
  [ST_IDLE] = on_idle,
  [ST_RUN]  = on_run,
  [ST_ERR]  = on_err,
};

st_t fsm_step(st_t cur, evt_t e) {
  st_t nxt = tab[cur](e);
  if (nxt != cur) log_state(cur, nxt);
  return nxt;
}

switch 版本：能跑，但改动成本高

对照看
switch (cur) {
case ST_IDLE:
  if (e == EV_BTN) nxt = ST_RUN;
  break;
case ST_RUN:

常见故障速查

现场先看这三条
环形缓冲偶发丢字节

先确认“谁写 head”是否唯一。ISR 与主循环同时写 head 就是多生产者；改用双缓冲、消息队列，或每生产者私有 ring。另一个高频原因是消费者读取速度长期低于生产速度，满拒绝被静默忽略。

对象池返回坏指针 / 对齐异常

块大小没有对齐到最大对齐要求，或池基址未对齐。用 _Alignas(8) / aligned(8) 修正基址，块大小向上取整到 8 的倍数；不要在池上做类型双关。

状态机卡死 / 链表遍历崩溃

FSM：事件丢失且无超时兜底，补默认迁移并记录日志。链表：遍历中删除未用 _safe 版本；删除后未重新初始化节点，导致二次插入。

时间轮的两个工程细节

单级不够用怎么办
/* 单级轮：只支持 < WHEEL_SIZE tick 的延时 */
void wheel_tick(void) {
  static uint32_t cur = 0;
  cur = (cur + 1) & (WHEEL_SIZE - 1);
  list_for_each_safe(p, tmp, &wheel[cur]) {
    tmr_t *t = container_of(p, tmr_t, node);
    list_del(&t->node);
    t->cb(t->arg);
    if (t->period) wheel_insert(t, t->period);
  }
}
长定时器：两级时间轮 = 毫秒轮 + 秒轮。长周期定时器先挂在秒轮，临近到期时“降级”插入毫秒轮；Linux 内核的 timer wheel 也是同一思想。
与 RTOS 的关系：FreeRTOS 的软件定时器用“命令队列 + 定时器列表”实现类似效果；不要在每个任务里撒一堆 vTaskDelay 来做周期调度。
