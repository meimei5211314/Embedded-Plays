三条最容易记混的规则

LR 的 bit0 = 1
表示 Thumb 状态。函数指针被截断成偶数地址，跳到目标时就会触发 INVSTATE。
读 PC 得到当前指令 + 4
这是流水线可见效应；反汇编归因时不要被这个偏移骗到。
xPSR.IPSR == 0
表示线程模式；非 0 表示当前在某个异常/中断里。它决定了你该看 MSP 还是 PSP。

为什么 PUSH {r4, lr} / POP {r4, pc} 能返回

栈帧的最小闭环
; 进入函数时 PUSH {r4, lr} ; SP -= 8；[SP]=r4，[SP+4]=lr ... POP {r4, pc} ; r4=[SP]，pc=[SP+4]，SP += 8 ; pc 被赋成返回地址，等价于 BX LR
注意：如果被调函数内部还要调用别人，LR 会被新的 BL 覆盖，所以必须在序言里先把 LR 压栈；这就是 PUSH {..., lr} 的原因。

Q1：printf 能不能放进 HardFault handler？

不建议。printf 可能重入、阻塞、使用堆，甚至在 fault 状态下再次触发 fault。最小取证路径应是纯寄存器操作 + 内存拷贝；UART 输出放在确认现场已保存之后，或者只写固定长度的十六进制。

Q2：为什么 objdump 看不到源码混合？

三个条件缺一不可：编译带 -g、ELF 未 strip、objdump 加 -S。预编译 SDK 的 .a 往往没有调试信息，只能看纯汇编。

Q3：-O2 下 PC 指向的行和实际肇事行不一致怎么办？

-O2 会重排、内联和合并指令。把 PC 在 fw.asm 里前后各看几条，结合 LR、反汇编和 map 文件判断；开发期可用 -Og 复现，但不要为了排障长期关优化。

Q4：M0+ 没有细分 CFSR，怎么定位？

M0+ 只有 HardFault，缺少 MemManage/BusFault/UsageFault 的细分状态。只能更多依赖 PC/LR、栈扫描、代码审查和二分注入；这也是为什么在 M0+ 上更要保留符号和复现实验。
