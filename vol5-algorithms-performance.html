A0.3 前置基石二：时域/频域双视角直觉

  • 同一信号的两种照片：示波器看的是时域(什么时候多大)；频谱仪/FFT 看的是频域(由哪些频率组成)。两者信息等价，视角互补；
  • 滤波器的两种身份：时域看是「平滑/延迟」，频域看是「低通/高通衰减曲线」——A1 的 RC 在时域叫一阶滞后，在频域就是 −20dB/dec 的低通；
  • 卷积定理一句话：时域卷积 = 频域乘积。这就是「为什么查表乘加就能实现滤波」的数学根源(A1/A9 都靠它)；
  • 带宽与延迟的对偶：任何让信号更平滑的操作都会引入延迟——本篇反复出现的主题，控制环设计的第一约束。

A1.3 可复用 C 实现（统一接口风格）

/* ── 1) O(1) 滑动平均(环形和增量更新) ── */
typedef struct { int32_t sum; uint16_t buf[64]; uint8_t idx,N; } ma_t;
void ma_init(ma_t*f,uint8_t N){ memset(f,0,sizeof* f); f->N=N; }
int16_t ma_run(ma_t*f,int16_t x){
    f->sum -= f->buf[f->idx];                 // 减最老
    f->sum += (f->buf[f->idx]=x);             // 加最新
    if(++f->idx>=f->N) f->idx=0;
    return f->sum / f->N;
}
/* ── 2) 中值滤波(3点插入法，N 大用窗口排序) ── */
int16_t med3(int16_t a,int16_t b,int16_t c){
    if(a>b){if(b>c)return b;return a>c?c:a;}   /* 经典三分支 */
    if(c>b)return b; return a>c?a:c;
}
/* ── 3) 一阶滞后： α=1-e^(-T/τ)，定点 Q15 查表替代 exp ── */
q15_t rc_run(rc_t*f,q15_t x){
    f->y += (q31_t)alpha_q15 * (x - f->y) >> 15;   /* Q15×Q15 右移 */
    return f->y;
}
/* ── 4) 组合拳模板： 限幅→中值3→一阶滞后 (采集链黄金三段) ──
   int16_t v = clamp(raw,last,DELTA);
   v = med3(v, h1, h2);
   v = rc_run(&f,v);            —— 三层各司其职： 野点/脉冲/白噪 */

A1.8 一阶 RC 的三个等价参数：α / τ / f_c 互相换算

连续域原型： τ·dy/dt + y = x        （硬件 RC 低通的数学孪生）
离散化(前向欧拉，Ts=采样周期)：
  α = Ts/(τ+Ts) ≈ 1/(1+2π·f_c·Ts)
三个参数知道任意一个即可推出另两个：
  例① 「要滤掉 50Hz 以上」→ f_c=10Hz 取裕量 → Ts=1ms 时
       α = 1/(1+2π×10×0.001) ≈ 0.94? 校验： f_c=10Hz → 2πf_cTs=0.0628 → α≈0.941
  例② 「阶跃后 100ms 到 63%」→ τ=100ms → α = 1ms/101ms ≈ 0.0099
记忆口诀：α 越接近 1 越「信新数据」，越接近 0 越「固执」。

A1.9 MA 的频响：为什么 N 点滑动平均能「完全吃掉」某些频率

MA 的频率响应 H(f)=sin(πfN/f_s)/(N·sin(πf/f_s)) —— sinc 形状：
· 直流增益 1（不改变平均值）✓
· 在 f=k·f_s/N (k=1,2,...) 处增益恰好为 0 —— 完全抑制！
工程应用实例：
  50Hz 工频干扰 + f_s=600Hz + N=12 → f_s/N=50Hz → 干扰被精确归零！
  这就是「采样率锁工频整倍数」策略的数学原理(A1.5 排故第三条的解药)。
副产物： 通带内也有轻微起伏(纹波)，且过渡带平缓——陡峭需求请上 IIR/FIR 设计工具。

A1.10 手把手数值例题：三步手算一阶 RC

已知： α=0.25, 初态 y=100, 输入序列 x=[200,200,200]
第1拍： y₁ = 100 + 0.25×(200−100) = 125
第2拍： y₂ = 125 + 0.25×(200−125) = 143.75
第3拍： y₃ = 143.75 + 0.25×(200−143.75) = 157.8
验证理论： 理论稳态 200；每拍剩余差距 ×0.75。
  n 拍后差距 = 100×0.75ⁿ → 要收敛到 ±5 内需 0.75ⁿ≤0.05 → n≈10.4 拍 ✓

  y += (8192×(x−y))>>15 —— 用 int32 中间量防溢出(ch03 纪律)。

A1.11 常见错误写法 vs 正确写法

// ✗ 错误1： Q15乘法忘右移 —— 输出瞬间飞到饱和
y += alpha_q15 * (x - y);
// ✓ 正确：

int16_t wma_run(wma_t*f,int16_t x){
    f->buf[f->idx]=x;
    int32_t acc=0,wsum=0,k=0;
    for(int i=f->idx;;i=(i+WN-1)%WN){          /* 从最新往回遍历 */

        wsum += w[k-1];
        if(k>=WN) break;

    if(++f->idx>=WN) f->idx=0;
    return acc/wsum;                            /* wsum=WN*(WN+1)/2 */
}

   传递函数(双零点对 ±ω0 + 双极点靠近零点)：

    float w0=2*3.14159f*f0/fs, cw=cosf(w0);
    f->b0=1; f->b1=-2*cw; f->b2=1;
    f->a1=-2*r*cw; f->a2=r*r; f->x1=f->x2=f->y1=f->y2=0;
}

    float y=f->b0*x+f->b1*f->x1+f->b2*f->x2-f->a1*f->y1-f->a2*f->y2;
    f->x2=f->x1; f->x1=x; f->y2=f->y1; f->y1=y;
    return y;
}

A2.1 一维 KF 五公式逐步推导（温度融合案例）

场景： 温度真值 x 缓慢变化；有两组观测——
  模型预测 x̂⁻（上一时刻值+漂移建模）方差 P⁻
  测量 z（ADC 读数）方差 R
① 预测：   x̂⁻ = A·x̂ + B·u        （A=1 无激励时就是「沿用上值」）
② 方差传播：P⁻ = A²·P + Q           （Q=过程噪声：模型有多不靠谱）
③ 增益：    K = P⁻/(P⁻+R)           （谁的不确定性小听谁的——比值即权重！）
④ 修正：    x̂ = x̂⁻ + K(z − x̂⁻)     （残差×增益）
⑤ 更新：    P = (1−K)·P⁻            （吸收测量信息后不确定性变小）
直觉锚点：
  R>>P⁻ → K→0 → 几乎不信测量(测量很烂)
  R<
💡 直觉锚点：K 是「按不确定性加权的自适应滑动平均」

R ≫ P⁻（测量很烂）→ K→0 → 几乎不信测量；R ≪ P⁻（模型很烂）→ K→1 → 几乎全信测量。A1 篇的 RC 低通就是 K 为常数的特例——卡尔曼把「信谁多一点」变成了随不确定性自动调节的量。

/* 场景： NTC 热敏(噪声大响应快) + DS18B20(准但慢 750ms) 融合 */
typedef struct { float x,P; float Q,R; } kf1_t;
void kf_init(kf1_t*k,float init,float q,float r){ k->x=init;k->P=1e4; k->Q=q; k->R=r;}
float kf_step(kf1_t*k,float z_fast,float z_slow,bool slow_valid){
    /* ①② 预测： 温度惯性大，模型=匀速漂移可扩展为 x+=v*dt */
    k->P += k->Q;
    /* ③④⑤ 修正： 两观测顺序修正等价于联合 */
    k->K = k->P/(k->P+k->R_fast);
    k->x += k->K*(z_fast - k->x);  k->P *= (1-k->K);
    if(slow_valid){                    /* 慢但准的每秒来一次拉基准 */
        float K2=k->P/(k->P+k->R_slow);
        k->x += K2*(z_slow-k->x);      k->P*=(1-K2);
    }
    return k->x;
}
/* 定点版(Q15)： 全程乘加右移；P 用 int32 表示 2^-16 尺度——
   M0 上 ~40 cycles/步，比浮点快 3 倍且无库依赖 */

A2.5 EKF：非线性世界的通行证（IMU 融合框架）

姿态角与陀螺仪是非线性关系（欧拉角三角函数/四元数乘法），EKF 只需在三个位置「换非线性件」：

  1. 预测：直接用非线性 f(x,u) 算 x̂⁻；
  2. 方差传播：用雅可比矩阵 F=∂f/∂x 在工作点线性化；
  3. 观测：同样线性化 H=∂h/∂x。

姿态融合的工程实现建议：

  • 状态选 [四元数 q(4) + 陀螺零偏 b(3)]，用误差状态（error-state）做 EKF——数值更稳，这就是 ESKF，飞控标配（Madgwick/AHRS 库内核同源）；
  • 协方差对称化 P=(P+Pᵀ)/2，防 float 累积误差发散。
⚠️ 何时别上 EKF

单变量缓变过程（A2.2 的标量 KF 已够用）；强非线性突变场景（考虑 UKF 或粒子滤波）。不要为了「高级」而上 EKF——调不好的 EKF 不如调好的互补滤波。

A2.9 增益公式为什么是 P/(P+R)：最小方差推导

问题： 两个独立高斯估计——预测 x̂⁻(方差P⁻) 与测量 z(方差R)，最优融合？
设融合结果 x̂ = w·z + (1−w)·x̂⁻，求 w 使融合方差最小：
  Var(x̂) = w²R + (1−w)²P⁻        （独立方差相加）
  d/dw = 0 → 2wR − 2(1−w)P⁻ = 0
  → w = P⁻/(P⁻+R)                 ★正是卡尔曼增益！
  代回得 Var_min = P⁻R/(P⁻+R) = (1−K)P⁻   —— 即更新方程⑤。
🔑 结论：KF 的本质

KF 就是「按不确定性加权的自适应平均」——五个公式里只有③（增益）需要「想」，其余都是代数搬运。上面这段两行推导就是它的全部秘密。

A2.11 多维矩阵形式讲解（通往 EKF 的桥）

n 维状态、m 维观测时五个公式的矩阵版：
  x̂⁻ = F·x̂ (+B·u)          F=状态转移矩阵： 描述「模型认为状态怎么演化」
                            例匀速运动： x=[位置,速度]ᵀ → F=[[1,dt],[0,1]]
  P⁻ = F·P·Fᵀ + Q           Q 变成 n×n 矩阵——对角线=各状态自身过程噪声，
                              非对角=状态间相关性(通常先置 0)
  K  = P⁻·Hᵀ·(H·P⁻·Hᵀ+R)⁻¹   H=观测矩阵： 「从状态到测量的投影」
                              只测温度不测速度 → H=[1,0]
  x̂  = x̂⁻ + K(z−H·x̂⁻)
  P   = (I−K·H)·P⁻
💡 读懂矩阵版

标量版的除法在矩阵版变成「乘 Hᵀ 再乘逆」——本质不变。工程上永远用对称正定求解器/平方根分解处理，不要手写求逆。

/* NIS = z̃² / (P⁻+R) ： 归一化新息平方，健康滤波器应均值≈1 */
typedef struct { float s; uint16_t n; } nis_t;
void nis_feed(nis_t*h,float z,float xhat_pred,float p_pred_plus_r){
    float nis=(z-xhat_pred)*(z-xhat_pred)/p_pred_plus_r;
    h->s+=nis; if(++h->n>=200){
        float mean=h->s/h->n; h->s=0; h->n=0;
        if(mean>2.0f)  log_warn("KF:Q too small (lagging)");
        if(mean<0.4f)  log_warn("KF:Q too large (noisy out)");
    }
}
/* 判读依据： 一致时 NIS 服从自由度 m 的卡方分布(m=观测维数)，
   单维均值期望 1.0，[0.5,2.0] 可接受 —— 这是「调参有据」的核心工具。 */

── EKF 一步 ──
① 预测： x̂⁻ = 9.0 ; P⁻ = 0.5 (+Q≈0)

   x̂ = 9.0 + 0.372×0.5 = 9.19V
⑤ 更新： P=(1−K·H)·P⁻=(1−0.669)×0.5=0.166

A3.3 Mahony 完整实现（含 Kp/Ki 与零偏估计）

/* 核心： 用重力+地磁构造误差向量 e，PI 反馈修正四元数与陀螺零偏 */
void mahony_update(float gx,float gy,float gz,       // rad/s
                   float ax,float ay,float az,       // 归一化后
                   float mx,float my,float mz, float dt){
    /* ① 由当前四元数旋转「参考重力」到机体系 → 预测的加计读数 */
    q2rot(&q, R);  vx=R[1][2]*? ...                    // 标准两行式见开源库
    /* ② 误差 = 测量叉乘 预测 (向量误差即旋转修正量) */
    ex += (ay*rz - az*ry); ey += (az*rx - ax*rz); ez += (ax*ry - ay*rx);
    /* ③ 积分项估计陀螺零偏(Ki 通路)——这是 Mahony 比互补强的地方 */
    ix += Ki*ex*dt; iy += Ki*ey*dt; iz += Ki*ez*dt;
    /* ④ 比例项直接修正角速度(Kp 通路)，再积分更新四元数 */
    gx_corr = gx + Kp*ex + ix; ...
    qUpdate(gx_corr,gy_corr,gz_corr,dt);
}
/* 调参口诀： Kp 决定「拉回力度」(0.5~5 常用，大=跟快但抖)；
   Ki 从 0 起步，仅当存在可观测恒定漂移时缓慢加(0.001 级)；
   振动平台： 先降 Kp 到不抖，再靠 Ki 补精度。 */

A3.9 四元数基础补课：为什么不用欧拉角

欧拉角的致命伤——万向锁(Gimbal Lock)：
  pitch=90° 时，roll 轴与 yaw 轴在空间中重合 → 丢一个自由度，
  此时微小扰动引起 roll/yaw 疯狂互换(视频里无人机翻转失控的经典画面)。
四元数 = 一个旋转轴 n̂ + 转角 θ 的紧凑编码：
  q = [cos(θ/2), sin(θ/2)·n̂x, sin(θ/2)·n̂y, sin(θ/2)·n̂z]
四大红利：
① 无奇异点(任意姿态都有唯一表示)
② 组合两次旋转 = 四元数乘法(16 次乘法，比旋转矩阵省)
③ 归一化只需除以模长——数值稳定
④ 与旋转矩阵互转公式固定，SVD? 不需要——标准公式抄即可
工程纪律：内部永远用四元数传递，只在输出给人看时转欧拉角。

A3.11 Mahony 误差叉乘的几何意义

为什么是叉乘(cross product)？
  e = a_measured × a_predicted
  叉乘向量的方向 = 把「预测重力」转到「测量重力」所需旋转轴；
  叉乘的模长 ∝ 两向量夹角正弦 = 需要修正的角度大小。
所以 e 天然就是一个「旋转修正量」：
· Kp·e 直接叠加到陀螺读数上 → 立即把姿态往测量方向拽；
· Ki·e 积分后成为零偏估计 → 温漂被慢慢学走。
对比互补滤波的标量比例： 叉乘版本天然处理三维耦合，无需逐轴调参——
这就是 Mahony 更优雅的根源。

A3.12 磁力计校准完整流程（硬铁+软铁）

  1. 数据采集：设备缓慢做「立体 8 字」翻滚 ≥2 分钟，覆盖尽可能多的姿态，采 ≥2000 点原始 mag 三元组；
  2. 硬铁偏移(hard-iron)：每轴取 (max+min)/2 得偏置 b——这是板上永磁体/电流产生的恒定磁场，减掉即可；
  3. 软铁畸变(soft-iron)：理想轨迹应为球面，实际因金属环境变成椭球——用最小二乘拟合椭球求 3×3 校正矩阵(入门版可只做各轴缩放归一)；
  4. 验证判据：校正后的点云应落在以原点为心的球面上，半径=当地地磁强度(约 0.5 Gauss)；
  5. 部署注意：校准结果随整机结构变化(换壳/换安装位即失效)——产线逐台校准或引导用户八字校准流程。

A3.8 补充①：四元数微分方程 dq/dt = ½·q⊗ω 推导与代码

/* 直觉推导：
   机体角速度 ω(x,y,z) 在 dt 内造成一个小旋转 Δq=[1, ω·dt/2]
   新姿态 = 旧姿态 ⊗ 小旋转 → 展开取一阶近似：
   dq/dt = ½ · q ⊗ [0, ωx, ωy, ωz]        ★四元数右乘角速度纯四元数 */
void quat_integrate(float*q,float gx,float gy,float gz,float dt){
    float dq[4]={
        -0.5f*(q[1]*gx + q[2]*gy + q[3]*gz),          /* q0' */
         0.5f*(q[0]*gx + q[2]*gz - q[3]*gy),          /* q1' */
         0.5f*(q[0]*gy - q[1]*gz + q[3]*gx),          /* q2' */
         0.5f*(q[0]*gz + q[1]*gy - q[2]*gx)};          /* q3' */
    for(int i=0;i<4;i++) q[i]+=dq[i]*dt;
    /* 归一化(必须！数值积分会让模长漂移)： */
    float n=1.0f/sqrtf(q[0]*q[0]+q[1]*q[1]+q[2]*q[2]+q[3]*q[3]);
    for(int i=0;i<4;i++) q[i]*=n;
}
/* 精度升级： 二阶积分(RK2)或子步进(sub-step)——200Hz 下欧拉已够，
   400Hz+ 高动态场景再升级。 */

A4.3 工业级增量式 PID 参考实现（全文）

typedef struct {
    float Kp,Ki,Kd, dLPF_beta;
    float e1,e2, d_prev;          /* 历史 */
    float out_min,out_max;        /* 执行器物理限幅 */
    float integ_max;              /* 积分项独立限幅 */
} pid_t;
float pid_run(pid_t*p,float set,float pv){
    float e=set-pv;
    float d_raw = (pv < p->e1) ? (p->e1 - pv) : -(pv - p->e1); /* PV 微分先行 */
    float d = p->dLPF_beta*d_raw + (1-p->dLPF_beta)*p->d_prev; /* 不完全微分 */
    p->d_prev = d;
    float du = p->Kp*(e - p->e1) + p->Ki*e + p->Kd*(d - ? );   /* 见下注 */
    /* ↑ 完整增量式: Kd 用二阶差分；工程上常以滤波微分直接乘 Kd 简化 */
    float u_new = clamp(u_prev + du, p->out_min, p->out_max);
    /* 抗饱和(clamping)： 输出贴边且误差同向 → 回退本次积分贡献 */
    if((u_new==p->out_max && e>0)||(u_new==p->out_min && e<0))
        du -= p->Ki*e;
    if(fabsf(e)<p->integ_max) u_prev += du; else u_prev += du - p->Ki*e*? ; 
    p->e2=p->e1; p->e1=e;
    return u_prev;
}
/* 注： 以上骨架展示全部要素的组合方式；完整可编译版请对照
   「PID without a PhD」(Tim Wescott) 与 ARM PID 库逐行核对符号约定。 */

A4.9 增量式公式的「过去·现在·未来」解读

Δu[k] = Kp·(e[k]−e[k−1]) + Ki·e[k] + Kd·(e[k]−2e[k−1]+e[k−2])
         └── 现在 ──┘      └─ 过去 ─┘    └──── 未来趋势 ────┘
· Kp 项： 本轮比上轮恶化多少，立即加倍纠正；
· Ki 项： 只要还有偏差就持续推；
· Kd 项： 二阶差分≈加速度——误差增速放缓=接近目标，提前松劲防超调。
增量式三大红利：
① 输出天然是累积量，切手动时冻结 Δu 即无扰；
② 无独立积分累加器(饱和由输出限幅直接体现)；
③ 公式无大数相减，定点实现友好。
代价： 积分截断细节自己做(A4.2)，且丢失 u 绝对语义(需保存 u_prev)。

A4.10 微分先行：为什么对 PV 微分而不是对误差微分（证明）

设设定值阶跃： r 从 0 跳到 R₀
· 对误差微分： de/dt = d(r−y)/dt = dR₀/dt − dy/dt → 阶跃瞬间出现冲激 δ(t)
  → Kd×δ = 输出无限尖峰！ —— 「改设定值输出猛跳一下」的元凶
· 对 PV 微分： d(−y)/dt = −dy/dt → 设定值怎么变都无关，
  只对「实际输出的变化率」反应 —— 平滑且物理意义正确。
结论： 微分项永远写 −Kd·dy/dt (注意符号)，而不是 Kd·de/dt。

A4.16 PWM 分辨率与积分器的隐形交互

  • 量化死区现象：PWM 10bit 时 |Δu|<1LSB 的修正被吞掉→系统小范围永久摆动(limit cycle)；
  • 对策：① 提高分辨率/载频换算；② Δu 加抖动(dither)打散量化；③ 接受 ±1LSB 死区并写入指标；
  • 审计方法：记录稳态 Δu 序列——长期 ±最小步长交替即 limit cycle 实锤。

A4.18 补充①：串级 PID 完整代码框架（双环嵌套）

/* 结构： 外环位置环(100Hz) → 内环速度环(1kHz)
   铁律： 内环 Ts 是外环整数分之一；外环输出=内环设定 */
typedef struct { float Kp,Ki,Kd; float e1,u; float omin,omax; } pid_ax_t;
/* 内环速度环(1kHz 定时器调用) */
float inner_run(pid_ax_t*p,float v_set,float v_fb){
    float e=v_set-v_fb;
    float du=p->Kp*(e-p->e1)+p->Ki*e;
    p->u += du;                       /* 增量累积 */
    if(p->u>p->omax){p->u=p->omax;} else if(p->u<p->omin){p->u=p->omin;}
    p->e1=e;
    return p->u;
}
/* 外环位置环(100Hz)： 输出即内环的 v_set */
void outer_run(pid_ax_t*outer,pid_ax_t*inner,float pos_set,float pos_fb,float v_fb){
    float e=pos_set-pos_fb;
    float v_set=outer->Kp*e+outer->Ki*(outer->e1+=e)*TS_OUT;   /* 简化示意 */
    outer->e1=e;
    v_set=clamp(v_set,-V_MAX,V_MAX);
    inner_run(inner,v_set,v_fb);      /* 级联闭合 */
}
/* 级联 Anti-Windup 关键： 内环饱和时通知外环冻结积分——
   实现： 内环返回饱和标志，外环检测到则跳过本轮 Ki 累加(A4.12 思想上浮一级)。 */

A5.1 前馈+反馈复合：把「已知」提前干掉

思想：反馈只能「事后纠错」，可测扰动/设定变化可以「事前补偿」——控制量 = u = u_FF + u_FB。两个经典案例：

案例可测量前馈项收益
云台增稳载体角速度 ω_base−ω_base × Kff 直接抵消载体运动PID 只处理残差，追踪延迟 80ms → 12ms
加热控温设定值斜坡的导数功率前馈（能量守恒算式）跟踪误差降一个量级，且 Kp 可以更小

工程要点：

  • 前馈系数标定 = 开环辨识一次（阶跃响应斜率），别拍脑袋；
  • 前馈通道也加限幅 + 滤波，防止测量噪声直灌输出；
  • 「前馈为主、反馈兜底」是高精度系统的通用配方。

环被控量带宽设计本案例参数
内环(电流)SSR 电流>10× 中环P 控制，100Hz，几乎瞬时

串级三条铁律：

  1. 内环必须显著快于外环——否则外环指令在内环眼里是噪声；
  2. 每环独立整定：先内后外，内环闭合且稳定后再动外环；
  3. 内环饱和要向外环传信号（Anti-windup 级联）——否则外环积分照样飞。
💡 适用判据：什么时候值得串级

被控对象存在「中间物理量既可测又能快速影响输出」才值得串级；否则单环 + A5.1 前馈更简单可靠。串级不是免费午餐——多一个环就多一倍整定与调试工作量。

A5.3 Smith 预估器：给大滞后装「时光机」

痛点：长管道温控 / web 张力等纯滞后 τ 占主导时，PID 看到误差时已晚了 τ 秒——无论怎么整定都在「震荡」与「迟钝」之间二选一。

Smith 预估结构：用对象模型 Gm(s)·e^(−τm·s) 并联一条「无滞后虚拟反馈」，让控制器实际调节的是预估的无滞后误差。嵌入式离散实现只需一条 FIR 延迟线（长度 N = τ/Ts）取模型输出：e_ctrl = set − y_meas_delayed_compensated。

⚠️ 模型失配是软肋

τ 或增益估偏 20% 以上，效果骤降。对策：在线一阶 + FOPDT 辨识（继电器法可顺带出模型），定期刷新模型参数——Smith 预估器永远和它的模型一样好。

A5.4 LQR 全推导与云台速度环实现 ★

对象(云台单轴速度环简化为二阶系统)：
  ẋ = Ax + Bu ,  x=[ω, i]ᵀ (转速,电流)
     A=[[0, k1],[0,-a]], B=[[0],[b]]
代价函数： J = ∫ (xᵀQx + uᵀRu) dt
最优解：  u = −Kx ， K=R⁻¹BᵀP ， P 由代数 Riccati 方程解得：
  AᵀP + PA − PBR⁻¹BᵀP + Q = 0
离线求解(主机 python scipy.linalg.solve_continuous_are)得到 K 向量，
MCU 端只需一行点积： u = −(K0*ω_err + K1*i_err) + u_ff
💡 Q/R 的直觉：一个调「狠」，一个调「省」
  • Q 加大对应状态分量 → 更激进压偏差（响应快、超允许忍）；
  • R 加大 → 更爱惜执行器（平缓省电）。

LQR 的工程红利：设计在 PC 完成（solve_continuous_are），运行期成本 ≈ 零——MCU 上就是一行点积。

/* 云台速度环 LQR 实现(F407, 10kHz) */
static const float K[2] = {-0.86f, -0.31f};   /* 主机解 Riccati 后固化 */
float lqr_speed(float w_err, float i_meas){
    float u = -(K[0]*w_err + K[1]*i_meas);    /* 状态反馈 */
    u += feedforward_from_gyro();             /* A5.1 前馈叠加 */
    return clamp(u, U_MIN, U_MAX);
}
/* 调参即改 Q/R 重解： ω 权重 ×10 → K0 变陡 → 阶跃恢复快 40%(实测)，

A5.14 补充①：离散 LQR 与 LQG 桥接

离散化两步走（工程标准流程）：

  1. 对象离散化：x[k+1]=Ad·x[k]+Bd·u[k]（Ad = e^(A·Ts)，用 c2d 工具）；
  2. 解离散 Riccati（DARE）：P = solve_discrete_are(Ad,Bd,Q,R)，然后 K = np.linalg.solve(R+Bd.T@P@Bd, Bd.T@P@Ad)。

LQG = LQR（状态反馈）+ Kalman（状态估计）的组合。分离定理：两者可独立设计再直接级联——估计器输出当真值喂给 LQR。

⚠️ LQG 的代价

各自稳定 ≠ 整体最优裕度——LQG 没有经典 LQR 的保证裕度，鲁棒性可能变差（Doyle 反例），实测验证不可省。

A5.15 补充②：MPC 最小示例（2 状态 horizon=3 暴力求解）

/* 思想演示： 把「未来 N 步的代价」显式算出来选当前最优 u —— MPC 的灵魂。
   对象： 一阶温度 x[k+1]=0.9x[k]+0.1u[k]，目标 r=50，约束 u∈[0,100] */
float mpc_step(float x){
    float best_u=0,best_J=1e30f;
    for(int ui=0;ui<=100;ui+=5){            /* 粗粒度枚举 u0 候选 */
        float J=0,xx=x,u=ui;
        for(int k=0;k<3;k++){                /* horizon=3 展开预测 */
            xx=0.9f*xx+0.1f*u;
            J += (xx-50)*(xx-50);            /* 状态代价 */
            J += 0.01f*u*u;                  /* 控制量代价(省能源) */
            u *= 0.8f;                       /* 简单衰减假设后续控制 */
        }
        if(J<best_J){best_J=J;best_u=ui;}
    }
    return best_u;                            /* 只执行第一步，下拍重算(滚动优化) */
}
/* 与 PID 的本质差异： 显式处理约束与未来；
   成本： 枚举法 O(candidates×N)；正式实现用 QP 求解器(A 核/M7+)。

typedef enum {IF_ACCEL, IF_STEADY, HANDOVER, CLOSED_LOOP} ifst_t;
void if_sm_step(float*id_ref,float*theta_if,float theta_obs,float spd){
    static ifst_t st=IF_ACCEL; static float blend=0;
    switch(st){
    case IF_ACCEL:                        /* 电流频率斜坡上升 */
        *theta_if += omega_ramp*DT;
        if(spd >= SWITCH_SPD){ st=IF_STEADY; hold_timer=0; }
        break;
    case IF_STEADY:                       /* 恒速保持，等观测器收敛 */
        *theta_if += omega_now*DT;
        if(++hold_timer > HOLD_TICKS && obs_converged()) { st=HANDOVER; blend=0; }

    case HANDOVER:                        /* 角度加权混合： θ=blend·θobs+(1-blend)·θif */

        if(blend>=1.0f){ st=CLOSED_LOOP; }
        break;
    case CLOSED_LOOP: break;              /* 正常无感运行 */
    }
}

A7.1 梯形速度曲线：三段式与在线化

/* 离散在线版(每控制周期走一步)——嵌入式首选，无需预计算整条曲线 */
typedef struct { float pos,vel,acc; float vmax,amax; int32_t target; } trap_t;
void trap_step(trap_t*t){
    float d_rem = t->target - t->pos;
    /* 判定减速距离： v²/(2a) —— 经典运动学 */
    float d_dec = t->vel*t->vel/(2*t->amax);
    if(d_rem <= d_dec && t->vel > 0)        t->acc = -t->amax;  // 必须减速
    else if(t->vel < t->vmax)               t->acc = +t->amax;  // 还可加速
    else                                     t->acc = 0;
    t->vel = clamp(t->vel + t->acc*TS, 0, t->vmax);
    t->pos += t->vel*TS;
    if((d_rem<=0 && t->vel>=0) || (t->vel==0 && fabsf(d_rem)<1)) { t->pos=t->target; t->vel=0; }
}
/* 三种边界情况必须单测：
① 目标太近(vmax 都没到就要减速) → 自动退化为三角形 ★高频漏测
② 中途反向新目标 → 以当前状态为初值重算，禁止跳变
③ 减速段到达但速度未归零 → 位置钳位+速度归零的收敛兜底 */

A7.9 手把手数值例题：梯形三段时长手算

已知： d=0.3m, vmax=0.8m/s, amax=2m/s²

② 加速段： t_a=v/a=0.4s ， 走过 s_a=v²/2a=0.16m
③ 减速段对称： t_d=0.4s, s_d=0.16m

A7.11 限位保护集成（安全链设计）

  • 回零(homing)流程状态化：找限位→退避→再慢速逼近→设零——做成独立 FSM 而非散落在业务里。

A8.1 CRC 参数化五元组(Rocksoft™ 模型)

同一个"CRC-16"在不同文档里结果不同的原因——五个自由度：
 Width(16) | Poly(0x8005) | Init(0xFFFF?) | RefIn/RefOut(输入输出反转) | XorOut
常见实例对照：
  MODBUS : 16, 8005, FFFF, true/true, 0000   ← 低字节先传
  CCITT-FALSE: 16, 1021, FFFF, false/false, 0000
  XMODEM : 16, 1021, 0000, false/false, 0000
  CAN    : 15, 4599, 0000, false/false, 0000
联调铁律： 两端先交换这五元组再写代码；用同一测试向量
("123456789" → CRC 应为已知值)做握手自检。

A8.4 汉明 SECDED 最小实现(72bit 数据字示例思路)

/* 原理： k 个校验位分别覆盖「下标二进制含该位」的数据位；
   接收端重算 syndrome： syndrome≠0 → 出错位号即 syndrome 本身 → 翻转纠错；
   再叠一个全局奇偶位区分「单错可纠 / 双错只报」。 */
uint8_t ham_syndrome(uint64_t word,uint8_t parity_all){
    uint8_t syn=0; for(int b=0;b<64;b++) if(word>>b&1) syn^=(b+1);
    syn ^= parity_all<<6? ... ;      // 展开为完整 SECDED 判定表
    /* 应用场景： 板载 ECC RAM(Cortex-M7+ECC SRAM 配置)，
       NOR Flash 的 ECC 由控制器自动附加——工程师要做的只是
       读 ECC 错误计数寄存器做健康监控(ch49 思想)。 */
}

A8.7 CRC 的数学本质：模 2 多项式除法（图解）

把报文看作一个大二进制数 M，除以生成多项式 G(x)，余数即 CRC：
  例： 数据 1010， G=x³+x+1 (即 1011, r=3)：
        101000 ← 数据左移 3 位(补 r 个 0)
      ⊕ 1011
        ────
         0010 0
       ⊕  1011
          ────
          00110? 手算继续 → 最终余数 = CRC
要点：
· 加法不进位/减法不借位(XOR) —— 所以是「模 2」算术
· 检错能力来源： 若传输错误多项式 E 能被 G 整除则漏检；
  G 选得好时 ≤r bit 的突发错误必被检出(突发≠G 首尾同时坏)
· 「查表法」成立的根源： XOR 的线性性 → 按字节预组合中间余数

A9.2 Goertzel：只要一个频率时的性价比之王

typedef struct { float coef,q1,q2; } goz_t;
void goz_init(goz_t*g,float target_hz,float fs){
    g->coef=2*cosf(2*3.14159f*target_hz/fs); }
float goz_run(goz_t*g,const q15_t*x,int n){     /* 流式逐样本 */
    for(int i=0;i<n;i++){ float t=x[i]+g->coef*g->q1-g->q2;
        g->q2=g->q1; g->q1=t; }                  /* 循环内仅 1 乘 2 加 */
    return sqrtf(g->q1*g->q1 + g->q2*g->q2 - g->coef*g->q1*g->q2); }
/* N=205@8kHz 检测 697Hz(DTMF)： ~410 cycles vs 同精度 FFT ~8000+
   定点版(q15 系数)在 M0 上依然轻松——门铃音/载波检测首选。 */

A9.8 补充：实数 FFT 的频谱对称性说明

rfft 只算一半的原因：实信号频谱共轭对称 X[N−k]=X*[k]，后半段是前半段的镜像——信息量减半，计算量也减半。工程要点：

  • 谱线 k 与 N−k 是同一频率的正负分量对；
  • 单边谱幅值恢复：|A| = 2·|X[k]| / (N·CG)（k≠0）；DC 与 Nyquist 不乘 2；
💡 一个诊断技巧

若看到「不对称」的谱 → 输入混入了复数/采样异常——此时问题不在频谱图，而在信号本身。

A10.8 HMAC 为什么能防长度扩展攻击（双层 key 图解）

朴素方案 MD5(msg‖key) 的死穴：
  SHA/MD5 类哈希的内部状态可被「接续」—— 攻击者拿到 MD5(msg‖key)
  后无需知道 key 就能计算 MD5(msg‖key‖padding‖恶意后缀) 的合法签名！
HMAC 的结构：
  HMAC = H( (K⊕opad) ‖ H((K⊕ipad) ‖ msg) )
  两层 key 异或不同常量(ipad/opad) → 内外两次完整哈希 →

A10.9 手把手数值例题：Varint 编码十进制 300

300 二进制 = 100101100 (9 位) → 需要 2 个字节(每组 7 位)
① 取低 7 位： 0101100 (44) → 还有高位剩余 → 输出字节 0b1_0101100 = 0xAC
② 剩余高 2 位： 10 (2) → 无更多位 → 输出字节 0b0_0000010 = 0x02
结果： [0xAC, 0x02] —— 2 字节表示 300
解码反向： 读 0xAC→最高位=1 继续；取低 7 位 0101100；
  读 0x02→最高位=0 结束；拼接 (2<<7)|44=300 ✓
对照定长 uint32： 4 字节 → Varint 在小数值域省 50%+。
温度 Δ×100 序列大多落在 ±63 内 → 单字节搞定(ch83 载荷瘦身实例)。

A10.11 Nonce 持久化设计（掉电不回退）

  • 问题：boot_counter 存 Flash，断电回退 → 重启后 nonce 重复 = 灾难性密钥流重放；
  • 方案 A：计数器存 eFuse/OTP 区单调递增(硬件保证不回退)；
  • 方案 B：双页交替写+页内序号比较(取大者)——掉电任意时刻至少一页有效且更大；
  • 方案 C(推荐组合)：RTC 备份域保存运行值 + 上电时与 Flash 持久值取 max 再回写——两层保险；
  • 验证实验：升级中随机断电 100 次，检查每次重启后的首帧 nonce 严格递增。

A11.3 AMCL：粒子滤波定位的思想内核

SO1.2 分析思路一：自顶向下分解法

任何「系统慢」都按固定层次拆解，每层只回答一个问题：

SO1.12 能效与性能的权衡：race-to-idle 与 EDP

  • Race-to-Idle 策略：以更高功率短时间完成工作，然后尽早进入深度睡眠——当「高频运行的平方级功耗」<「长时间低频的底噪功耗」时成立。实测例：某采集任务 @48MHz 跑 40mW×10s vs @96MHz 跑 25mW×5s+深睡 5s，后者能量省 37%；
  • DVFS 三策略选型：powersave(电池优先)/schedutil(跟随负载★默认)/performance(延迟优先)——切换依据是 SO1 预算表而非习惯；
  • EDP(Energy-Delay Product)：E×D 作为综合指标——同时惩罚能耗与延迟，比单看任一项更能反映「能效工程」目标；记录每次优化的 EDP 变化趋势。

SO1.13 容量规划入门：利特尔法则的两个应用例题

定律： L = λ × W   (系统内平均数量 = 到达率 × 平均驻留时间)
例① 队列深度设计：
   传感器突发到达 λ=2000 msg/s，处理线程单条 W=400µs → 需并发容量 L=0.8
   → 单消费者足够； 若 W=2ms → L=4 → 需 4 并行度或降 W。
例② OTA 分块窗口：
   端到端 RTT=300ms，期望同时在途块=8 → 最大吞吐=8/0.3s≈26 块/s
   → 反推分块大小以满足升级时限。
排队直觉(M/M/1 一句话)： 利用率 ρ 越接近 1，排队延迟按 1/(1−ρ) 发散——
   任何资源规划留 30% 余量的数学依据就在这里。

SO1.14 PGO 简介：为什么嵌入式很少用、替代方案是什么

  • 原理：PGO(Profile-Guided Optimization)用真实运行剖析数据指导编译器做内联/布局/分支预测优化；
  • 嵌入式冷遇原因：需要两阶段构建+代表性运行剖面；固件工况多样导致「训练剖面失配」风险；工具链支持碎片化；
  • 务实替代：① 手工热点引导——profiler TOP 函数集中 -O3(函数级 attribute)；② 关键路径代码物理布局(链接脚本排序提升 I-Cache 局部性)；③ A 核场景可评估 LLVM PGO 的可行性试点。

SO2.5 中断负载治理专项

中断负载审计三步(ch61 工具链落地)：
① 排名： /proc/interrupts 双采样差值 → 每秒次数排行(MCU: NVIC 计数器)
② 归因： 单 IRQ 高频三嫌疑——
   电平未清源(风暴 ch61)/阈值太灵敏(传感器抖动)/本该 DMA 化的逐字节中断
③ 治理组合拳：
   · 硬件消抖+软件确认窗(按键类)

SO3.8 动态优先级调整的五条陷阱清单

  1. 运行期改优先级破坏 RMS 前提——可调度性分析全部作废，必须重新验证(ch45)；
  2. 与互斥量继承协议冲突：PI 临时提升期间外部 vTaskPrioritySet 会踩掉继承值；
  3. 优先级饥饿窗口：动态提升的任务若忘记回落，永久霸占高优——提升必须绑定「作用域结束自动回落」；
  4. 调试不可复现：优先级随时间变化让问题无法稳定重现——所有动态调整必须打点留痕(ch14)；
  5. SMP 下语义变化：跨核迁移+优先级组合的行为因核而异(ch50A)——单核直觉不可平移。

/* ipc_bench.c —— 两任务乒乓 N 次取分布，任何 RTOS 移植后先跑它 */
#define BENCH_N 100000
static uint32_t cyc[BENCH_N]; static volatile uint32_t idx=0;
static TaskHandle_t hA,hB;
void taskA(void*a){                       /* 高优 */
    for(uint32_t i=0;i<BENCH_N;i++){
        uint32_t t0=DWT->CYCCNT;
        xTaskNotifyGive(hB);              // 触发 B
        ulTaskNotifyTake(pdTRUE,portMAX_DELAY);   // 等 B 回球
        cyc[idx++]=DWT->CYCCNT-t0;        // 一个完整往返
    }
    bench_report(cyc,BENCH_N);            // 输出 P50/P99/max
    vTaskDelete(NULL);
}
void taskB(void*a){
    for(;;){ ulTaskNotifyTake(pdTRUE,portMAX_DELAY);
             xTaskNotifyGive(hA); }
}

SO3.11 tickless 与任务架构联动调优案例

症状： 开启 tickless 后平均电流不降反升(180µA→240µA)。
Tracealyzer 泳道发现： 某低优统计任务每 500ms 醒一次 →
  每次唤醒都把「下一个 idle 窗口」切碎成 ≤500ms 小段，
  且每次唤醒都要重建 LP 定时器(开销 2ms×2mA)。
治理三步：
① 统计任务降频至 5s 并改用「攒批上报」；
② 其余周期任务对齐到同一节拍(相位合并, 减少唤醒次数)；
③ configEXPECTED_IDLE_TIME 提高，过滤碎片窗口。
结果： 平均电流 240µA→95µA。
启示： tickless 的敌人不是长任务而是「碎唤醒」——
架构层把唤醒源对齐合并，比调参数有效一个量级。

SO5.1 内核调参的语义级理解框架（举三反一）

参数族语义本质典型调优决策链
vm.dirty_ratio / dirty_background_*「脏页何时强制落盘」——写缓存水位线写入毛刺→降低 background 阈值让后台提前分担；掉电安全→缩短 expire 时间

SO5.2 cgroup v2 治理多服务争用实战

场景： 网关机上 MQTT 业务、日志采集、OTA 三者互相抢 CPU 与内存。
cgroup v2 统一层级方案：
/gateway.slice     cpu.weight=500  memory.max=256M    ← 业务主体让路给谁都不行
/logs.slice        cpu.weight=50   memory.max=64M     ← 日志永远低人一等
/ota.slice         cpu.weight=100  io.max="nvme0n1 wbps=50000000"
systemd 实现(推荐)： service 单元内直接写 CPUWeight=/MemoryMax=，
   或 systemctl set-property xxx.service CPUWeight=500 即时生效。
验证闭环： systemd-cgtop 实测各切片占比符合权重比；
   压力注入(模拟 OTA 满速)观察 MQTT P99 是否仍在预算表内(SO1 联动)。

SO5.3 eBPF 观测前沿：嵌入式能用吗？怎么用？

问题答案
ARM 板能跑吗？能——内核 4.x+ 开启 BPF_JIT/BPF_SYSCALL；低配板建议诊断会话时按需加载，平时零驻留
最有价值的三个程序① offcputime(off-CPU 火焰图数据源) ② biolatency(存储延迟直方图) ③ tcptop(每进程网络吞吐)
交叉编译痛点BPF 程序依赖目标内核 BTF——厂商内核常缺；对策 CO-RE+vmlinux.h 或退回 perf trace 方案
与 ch16 分工perf 回答「谁在耗 CPU」，eBPF 回答「谁在等/谁在丢」——互补不替代

SO5.4 io_uring 与异步 IO 前沿

价值定位： 高并发 IO(日志聚合/流媒体落盘)减少 syscall 与上下文切换。
嵌入式落地评估：
· 内核 ≥5.10： 主流 RK/i.MX 新 BSP 可满足
· 收益实测口径： 512 并发小文件写，io_uring vs epoll+pread/write
  → syscall 数 −90%，吞吐 +35%(x86 实测口径)；ARM 趋势一致
· 采用门槛判定： profiler 证明 IO 为瓶颈且应用已有事件循环架构
  才值得重构 —— 否则收益覆盖不了改造成本。

SO5.8 内存回收深水区：watermark/compaction/kswapd 联动

三级水位(min/low/high)驱动回收节奏：
· free < low → 唤醒 kswapd 后台回收(异步、温和)
· free < min → direct reclaim(同步——进程自己回收，延迟毛刺元凶)
· 高阶分配失败 → compaction 内存紧凑化(CPU 尖峰另一来源)
调优联动表：
  症状「偶发 50ms 卡顿周期性出现」→ vmstat 看 kswapd 时间戳是否对齐
    → 对策： 提前回收(watermark 刻度放大) / 关 THP / 关键进程 mlock(ch65)
  症状「高阶分配失败」→ /proc/pagetypeinfo 查碎片 → compact_memory 或重启预防

SO5.9 网络栈进阶：conntrack/RPS/RFS/XPS 分工速查

机制解决什么典型坑
conntrack有状态防火墙/NAT 连接表表满丢包！高 PPS 网关必调 nf_conntrack_max+超时；纯转发可 NOTRACK
RPS单队列网卡软中断跨核分发(软件)IPI 开销；小包高频收益明显
RFSRPS+按应用所在核定向(cache 亲和)需 rps_sock_flow_entries 配置
XPS发送队列与 CPU 绑定多队列硬件才有意义；与 RFS 配合锁核收益最大
组合拳顺序：XPS(发送绑核)→RPS/RFS(接收分发)→关闭 irqbalance 手工接管——每步跑 SO1 预算表验证。

SO5.10 观测体系分层架构：常态低频 + 问题态高频自动升降

设计目标： 平时不拖累生产流量，出事时能自动抓到现场。
三层结构：
L0 常态层(常驻)： 心跳携带 30s 粒度关键指标(CPU/mem/重传率/队列水位)
L1 触发层： 阈值/事件触发(错误率↑、延迟 P99 超标、OOM kill)
L2 深挖层(临时)： 自动 perf record -F299 -g --sleep 30 +
   eBPF offcputime + tcpdump 滚动窗口 → 打包上传后自动卸载
关键机制：
① 升级去抖： 连续 N 个窗口超阈值才升级，防抖动误报；
② 自我限流： L2 采集自身开销计入预算(<3%)，超限自动降级；
③ 现场保留： pstore/ramoops 兜底崩溃前的最后观测(ch64 联动)。
—— 这套分层就是 ch44 监控代理与 SO1 方法论的体系化合体。

一分钟闭卷

先自问，再翻讲义
  1. 采样决定上限
    闭卷自问：为什么采样率不够时，滤波也救不回信号？
    展开答案要点

    量化、混叠、噪声与采样率共同决定后续算法能看到什么；抗混叠要在采样前做。

  2. 滤波是延迟与噪声的交易
    闭卷自问：滤波带来的相位滞后如何影响闭环稳定性？
    展开答案要点

    RC、滑动平均、中值、EMA、Kalman 与互补滤波各有噪声模型与相位代价。

  3. 控制是约束下的取舍
    闭卷自问：积分饱和如何发生，抗饱和有哪些做法？
    展开答案要点

    PID、前馈、串级、LQR、SVPWM 与轨迹规划，都要受执行器、采样率和延迟约束。

  4. 数据链要可信
    闭卷自问：CRC 与 HMAC 各自防什么，不防什么？
    展开答案要点

    CRC/汉明/HMAC 解决不同威胁，FFT/Goertzel 提取频域信息，编码影响带宽与恢复能力。

  5. 性能要用预算与证据
    闭卷自问：如何证明一次优化没有把瓶颈推到别处？
    展开答案要点

    火焰图、perf、trace 与预算表定位瓶颈，优化前后必须用同一口径对比。

  6. 专家能力是方法论
    闭卷自问：给你一个 20 ms 的端到端延迟，你按什么顺序拆？
    展开答案要点

    诊断 → 预算 → 验证 → 复盘，比记住某个算法更重要；知识地图用来决定下一步查什么。

高频追问 · 先答后看

6 问
一阶低通的 α、τ、截止频率是什么关系？调 α 的代价是什么？

离散实现常用 α=dt/(τ+dt)，τ=RC，截止频率 fc=1/(2πτ)。α 越小越平滑，但相位滞后越大、响应越慢；截止频率必须远低于采样率的一半，否则离散化误差与混叠会破坏预期。

Kalman 滤波的预测/更新五步是什么？EKF 的误差来自哪里？

预测状态 x⁻=Fx+Bu，预测协方差 P⁻=FPFᵀ+Q；计算增益 K=P⁻Hᵀ(HP⁻Hᵀ+R)⁻¹；更新状态 x=x⁻+K(z−Hx⁻)；更新协方差 P=(I−KH)P⁻。EKF 通过对非线性模型求雅可比线性化，误差来自一阶近似与错误噪声模型。

积分饱和是怎么产生的？工程上怎么处理？

执行器达到限幅后，误差仍持续积分，积分项越积越大，退出饱和时就会严重超调。常用积分限幅、条件积分（饱和时停止积分）、反计算 back-calculation、微分先行与设定值加权；同时给执行器变化率限幅。

SVPWM 的基本思想是什么？死区为什么要补偿？

用相邻两个有效电压矢量与零矢量在一个 PWM 周期内合成参考矢量，七段式对称分配可降低谐波。死区防止上下桥直通，但会造成实际输出电压与占空比不符，需要按相电流方向补偿，否则低速时转矩脉动明显。

CRC、汉明码与 HMAC 分别适合什么场景？

CRC 检出随机/突发传输错误，计算便宜，不防主动篡改；汉明码能纠正单比特错误，适合存储或高可靠链路；HMAC 用密钥提供完整性与身份认证，能防篡改但需要密钥管理与防重放。选型先明确威胁模型。

拿到一张火焰图，怎样判断瓶颈是 CPU、内存还是 IO？

横轴宽度是采样占比，纵轴是调用栈；先找 self time 最大的函数，再看调用链。若热点集中在计算函数，查指令/分支/缓存；若集中在拷贝、缺页或锁，查内存与调度；若栈很浅但延迟高，查 IO 等待、中断与阻塞。结合 perf stat 与 trace 交叉验证。
